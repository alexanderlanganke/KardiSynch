Feature Handover

QR Code Export — KardiSync to CardioPal

Encodes visit follow-up data as a scannable QR code in CardioPal's HCP envelope format, enabling direct patient import from the clinic screen.

What was built

A third view mode (qr) in ViewPane's Raw/Formatted toggle. Selecting it renders an inline QR code containing the visit's clinical data — battery status, lead measurements, thresholds — in the JSON format that CardioPal's HCP QR scanner expects. The patient scans the code with CardioPal to import their follow-up record.

The implementation is entirely renderer-side. No IPC changes, no main-process modifications. The mapping logic is a pure function with full unit-test coverage.

Lead-to-channel mapping

The key challenge is classifying leads across 5+ manufacturer naming conventions into three channels: atrial (a), right ventricle (rv), and left ventricle (lv). Classification uses the lead's type first, falling back to location.

Channel Type patterns Location patterns
a /atri|^A$|^RA$|A-Lead/i /right\s*atri|\bRA\b|\bA\b/i
rv /^RV$|RV-Lead|^RV\s/i /right\s*ventri|\bRV\b/i
lv /^LV$|LV-Lead|^LV\s/i /left\s*ventri|\bLV\b|coronary\s*sinus/i

Covers: Biotronik ("A-Lead", "RV-Lead"), Medtronic ("Atrial Lead", "RV Lead"), Abbott ("Atrium"), CIEDocR ("RA", "RV", "LV"), and location-based fallback ("Right Atrial Appendage", "Coronary Sinus").

CardioPal HCP envelope format

Defined in CardioPal/src/utils/hcpQr.ts. The envelope wraps all HCP-generated QR payloads:

{
  "v": 1,              // version — must be 1
  "t": "fu",           // type: "fu" (follow-up), "params", or "icm"
  "ts": 1722300000,    // creation timestamp (Unix seconds)
  "d": { ... }         // FuPayload — channel measurements + battery
}

FuPayload keys

KeyTypeSource
datestringreport.interrogation_date
a / rv / lvCompactMeasurementClassified leads
bvnumberreport.batteryVoltage (volts)
bsstringreport.batteryStatus (BOL/MOL/ERI/EOL)
lonumberParsed from batteryLongevity or additionalFields["Estimated Longevity"]

CompactMeasurement

KeyUnitSource
taVlead.threshold
tpmslead.pulseWidth
semVlead.sensing
imΩlead.impedance

All measurement keys are optional — omitted when the source value is empty, NaN, or undefined. Typical payloads are 200–500 bytes, well within the QR v40 limit of ~2,953 bytes.
